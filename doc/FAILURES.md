# Провалы и выводы

## 2026-11-16 — DMA XEX-парсер прошит без проверки верхнего уровня

- Сделал `xex_dma_loader` + `xex_boot_stub`, проверил в ISim **только сам парсер**
  (Pong и River high-XEX проходили).
- После этого собрал Go и сразу записал на SD, не проверив интеграцию
  `atari_atr_loader` + `xex_dma_loader` + SIO/`dsk_*`/`ld_*` mux в верхнем уровне.
- На железе Pong завис: `atr_ready=1`, `atr_scount=0x0E` (синтетический диск,
  а не стаб), SIO прочитал только сектора 1–3.
- Даже debug-сборку с `xex_mode/done/busy/state` успел запустить, но не довёл
  до чтения: пользователь остановил.
- Вывод: **нельзя шить в железо RTL-интеграцию, проверенную только на уровне
  подмодуля**. Нужен тест верхнего уровня (mux, reset, CDC, SIO/ld арбитраж) или
  пошаговое чтение debug до прошивки.

## 2026-11-16 — серия экспериментов вместо диагностики

- Долго перебирал ATR/OS/загрузчики (179-byte MiST, Tang v2, Altirra OS,
  synthetic ATR), не отделив сразу:
  - битый/картриджный XEX;
  - необходимость BASIC off;
  - поведение OS SIO с `$D301`;
  - ограничения ATR-пути.
- Это стоило времени и доверия. Правильнее было сначала:
  1. проверить XEX в эмуляторе с выключенным BASIC;
  2. прогнать один нормальный low-XEX (Pong) на железе;
  3. только потом строить synthetic/DMA.

## 2026-11-17 — DMA XEX до coldstart: OS стирает RAM

- `xex_dma_loader` писал сегменты в Atari RAM **до** запуска OS (машина
  держалась в reset через `xex_busy`/`xex_hold`).
- Altirra OS coldstart стирает RAM с `$0008` до верха:
  `$EF1F: LDX $06 / LDY #$08 / LDA #$00 / STA ($66),Y ...` (ROM
  `altirraos-xl.rom`, reset `$EEBF`). Поэтому все DMA-сегменты исчезали
  ещё до чтения boot-секторов.
- Стаб при этом действительно запускался, но `JMP $4000` попадал в нули
  (`BRK`/warmstart) — на экране оставался тот же memo pad с курсором.
- Вывод: FPGA-DMA можно делать **только после coldstart** (стаб должен
  дождаться/запустить парсер и опросить флаг готовности), либо грузить
  файл через SIO после boot, как synthetic-ATR-загрузчик.
- Прямой `JMP` вместо `JMP ($02E0)` был необходимым, но недостаточным
  фиксом: векторы чистились вместе со всей RAM.

## 2026-11-17 — `$D301=$FD` включал BASIC, а не выключал

- Synthetic-загрузчик писал `PORTB=$FD` с комментарием «BASIC off».
- В этом ядре `basic_reg <= not(portb(1))`, т.е. `bit1=0` **включает**
  BASIC ROM на `$A000-$BFFF`. Miner 2049er копирует игру в `$8000-$BFFF`,
  верхняя половина уходила в ROM → «сломанный экран».
- Правильное значение — `$BF` (bit0=1 OS on, bit1=1 BASIC off), им же
  пользуется Altirra OS coldstart (`$EF0A..$EF19`).
- Вывод: не верить комментариям о полярности PORTB; проверять по
  `address_decoder.vhdl` и по поведению OS.

## 2026-11-17 — клавиатура: PS/2-байты пачкой и CDC

- Прошивка присылает все байты клавиши одной пачкой, по стробу на байт
  через 40 нс. Один toggle в `clk_host` — гонка: машина могла увидеть
  toggle уже после смены `ps2_code`, а соседние импульсы алиасились.
- Решение: `kg_async_fifo` 16×8 (clk_host → clk_sys) + читатель
  pop → wait → capture+toggle. Байт и strobe меняются вместе в clk_sys.
