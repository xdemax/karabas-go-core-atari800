# XEX: почему FPGA-DMA до boot не работает

## Симптом

Pong.xex примонтирован в Disk, cold reset: парсер завершается
(`xex_mode=1, xex_done=1, xex_busy=0`), SIO читает ровно 3 boot-сектора,
но на экране остаётся синий memo pad с курсором. Игра не стартует.

## Причина

`xex_dma_loader` писал сегменты в Atari RAM, пока машина была в reset.
После снятия reset OS делает coldstart и **стирает RAM**:

```text
Altirra OS XL, reset vector $EEBF:
$EF1F  LDX $06          ; число страниц (0 = 256)
$EF21  LDY #$08
$EF23  LDA #$00
$EF25  STA $66
$EF27  STA $67
$EF29  STA ($66),Y      ; очистка с $0008
$EF2B  INY
$EF2C  BNE $EF29
$EF2E  INC $67
$EF30  DEX
$EF31  BNE $EF29
```

То есть чистится всё от `$0008` до верха RAM — включая сегменты
`$4000-$447F`, которые только что записал DMA. К моменту `JMP $4000`
там нули; `BRK`/warmstart возвращает OS на memo pad. Векторы `$02E0/$02E2`
чистятся по той же причине.

## Что сделано сейчас

Raw `.xex` снова идёт через **synthetic-ATR + 6502-загрузчик**:
`atari_atr_loader` кладёт в SRAM 4 boot-сектора загрузчика и сырой XEX
с сектора 5; загрузчик запускается после coldstart и тянет файл через SIO,
поэтому очистка RAM ему не мешает. Этот путь уже работал на Go и не
зависит от DMA-арбитража.

`xex_dma_loader.v` / `xex_boot_stub.v` остаются в дереве, но в MiniG top
не инстанцируются.

## Как вернуть DMA правильно

1. До boot писать в SRAM только 3-секционный стаб (не сегменты).
2. Стаб запускается после coldstart, пишет magic в `$3F00` и опрашивает
   флаг `$3F01`.
3. FPGA по magic запускает парсер (сегменты уже после очистки RAM) и
   последним пишет `$3F01=1`; стаб читает `$02E0/$02E2`, вызывает INITAD
   и прыгает в RUNAD.
4. Писать в RAM во время работы CPU/ANTIC лучше через штатный DMA-порт
   ядра (`DMA_FETCH`/`DMA_ADDR`/`DMA_WRITE_DATA`/`MEMORY_READY_DMA`),
   а не через `ld_*`: `atari_sram` не очередь, одиночный `ld_req` может
   потеряться, если контроллер занят запросом CPU/ANTIC.

## Отдельно: PORTB

В этом ядре `basic_reg <= not(portb(1))`, и `portb(1)=0` выбирает BASIC
ROM на `$A000-$BFFF`. Значит `$FD` (bit1=0) **включает** BASIC, а не
выключает. Для BASIC off нужен bit1=1 (например, `$FF`), но при
RAM_SELECT != 0 биты 3:2 задают банк, поэтому правильнее
`LDA $D301 / ORA #$02 / STA $D301`. Проверить на River Raid.
