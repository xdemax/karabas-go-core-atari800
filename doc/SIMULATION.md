# Симуляция ядер Karabas в ISim (ISE 14.7)

Практическое руководство: как запускать RTL-симуляции модулей ядра без сборки
битстрима и без платы, что при этом проверяется, а что — нет.

Проверено на ISE 14.7 / ISim P.20131013, Linux x86_64, GCC 14+.

---

## 1. Зачем это нужно

Сборка `make minig` занимает ~15 минут (XST → ngdbuild → map → par → trce →
bitgen). Если ошибка в протоколе (SIO, загрузчик, тайминги видео), её дешевле
найти за секунды в симуляторе:

- проверить конечный автомат и обмен «запрос/ответ»;
- проверить арифметику адресов, счётчики, разбор заголовков;
- измерить тайминги видео (положение активной области, HS/VS/DE);
- отладить протоколы, которые на железе видны только «работает/не работает».

Симулятор **не заменяет** сборку и железо:

| Проверяет | Не проверяет |
|---|---|
| логику RTL, FSM, счётчики | синтез, BRAM/LUT, fit в кристалл |
| протоколы на уровне сигналов | timing (setup/hold), задержки платы |
| тайминги видео в цифре | аналог (DAC, уровни, кабель, монитор) |
| обмен с моделями памяти/устройств | реальную SD-карту и прошивку MCU |
| | метастабильность, джиттер, PLL на железе |

Типичный порядок: **симулятор → XST/сборка → плата**.

## 2. Окружение

ISE 14.7 установлен в `/opt/Xilinx/14.7/ISE_DS`:

```sh
source /opt/Xilinx/14.7/ISE_DS/settings64.sh
```

ISim состоит из двух частей:

- `fuse` — компилятор HDL + генератор C-кода и исполняемого файла симуляции;
- `isim` — собственно симулятор (batch по Tcl или GUI).

Проверка:

```sh
which fuse isim
fuse -h | head
```

> **Важно:** `settings64.sh` — bash-скрипт. В `zsh` его надо запускать через
> `bash -c 'source ...; ...'`, иначе `fuse: command not found`.

---

## 3. Проблема современного GCC и обход

ISim 14.7 генерирует C-файлы, в которых вызываются функции `*_init()` **без
прототипов**. Старые GCC (4.x) считали это предупреждением, GCC 14+ — ошибкой:

```
error: implicit declaration of function ‘work_m_..._init’
FATAL_ERROR:Simulator:Fuse.cpp:500 - Failed to compile generated C file
```

`fuse` жёстко вызывает `/usr/bin/gcc` (строка зашита в бинарнике). Решение —
запускать **копию** `fuse`, в которой путь компилятора заменён на обёртку,
добавляющую `-Wno-implicit-function-declaration`.

Ключевой момент: `/usr/bin/gcc` — ровно 12 символов. Замена должна быть такой
же длины, иначе разваливается разбор строки внутри бинарника. Используем
`/tmp/xxx/gcc` (тоже 12 символов).

```sh
mkdir -p /tmp/xxx
cat > /tmp/xxx/gcc <<'EOF'
#!/bin/sh
exec /usr/bin/gcc -Wno-implicit-function-declaration "$@"
EOF
chmod +x /tmp/xxx/gcc

cp /opt/Xilinx/14.7/ISE_DS/ISE/bin/lin64/unwrapped/fuse /tmp/opencode/fuse_patched
python3 - <<'EOF'
p = '/tmp/opencode/fuse_patched'
d = open(p, 'rb').read()
assert d.count(b'/usr/bin/gcc') > 0
d = d.replace(b'/usr/bin/gcc', b'/tmp/xxx/gcc')
open(p, 'wb').write(d)
EOF
```

Дальше везде запускаем `/tmp/opencode/fuse_patched` вместо `fuse`. Установленный
`fuse` не трогаем.

> `/tmp` очищается при перезагрузке — скрипт `sim/run_isim.sh` создаёт обёртку и
> патченый `fuse` заново, если их нет.

Альтернативы, если патч не нравится:

- поставить старый GCC (4.x–12) и заменить строку на его путь (тоже 12 символов);
- запускать ISE в контейнере/дистрибутиве со старым GCC;
- вручную править сгенерированный `*_main.c` и линковать (сложно, не
  рекомендуется).

## 4. Кириллица в путях

ISim 14.7 плохо переваривает **абсолютные пути с не-ASCII** в `.prj`:

```
Analyzing Verilog file " " into library work
```

(имя файла превращается в пустую строку). Поэтому:

- в `.prj` используйте **относительные ASCII-имена** (`dut.v`, `../rtl/foo.v`);
- надёжнее всего — запускать симуляцию из **ASCII-каталога** в `/tmp`
  (как это делает `sim/run_isim.sh`), скопировав туда нужные исходники;
- не указывайте в `.prj` абсолютные пути, особенно с кириллицей.

## 5. Быстрый старт

Готовый пример — SIO-ответчик (`sim/tb_sio.v`). Запуск:

```sh
sim/run_isim.sh sio
```

Скрипт:

1. копирует `src/rtl/atari_sio_disk.v` в `/tmp/opencode/isim_sio/dut_sim.v`
   (и уменьшает `ACK_CYCLES` для скорости);
2. копирует `sim/tb_sio.v`;
3. создаёт `.prj`;
4. собирает (`fuse_patched`) и запускает (`./tb_sio -tclbatch run.tcl`);
5. печатает результат.

Ожидаемый вывод:

```
tb_sio: 0 errors
```

Второй пример — загрузчик ATR:

```sh
sim/run_isim.sh atr
```

Ожидаемо:

```
tb_loader: 0 errors, 92672 bytes written
```

Системный тест ATR-loader + DMA XEX-парсер + SIO (Pong, `sim/pong.hex`):

```sh
sim/run_isim.sh xex
```

Ожидаемо: `tb_xex_system: PASS` (это тест **DMA-модуля**; в текущем top
XEX идёт через synthetic-ATR, см. `doc/XEX_ATR.md`).

Кадр видео (720×576, реальная геометрия строки ANTIC):

```sh
sim/run_isim.sh video
# /tmp/opencode/isim_video/frame.ppm

sim/run_isim.sh video_compare
# /tmp/opencode/isim_video_compare/frame_a.ppm, frame_b.ppm
```

`tb_video_frame` печатает `rows 48..527` (PAL, поля 48/48) и колонки
маркеров; `tb_video_compare` — то же для окон A (88) и B (78).

## 6. Анатомия тестбенча

Минимальный каркас (Verilog):

```verilog
`timescale 1ns / 1ps
module tb_foo;
	reg clk = 0;
	always #17.5 clk = ~clk;          // 28.571 MHz

	reg reset = 1;
	// ... сигналы DUT ...

	foo dut (.clk(clk), .reset(reset), ...);

	integer errors = 0;

	// сторожевой таймер: не даёт симуляции висеть вечно
	initial begin
		#20_000_000;                    // 20 ms
		$display("TIMEOUT");
		$finish;
	end

	initial begin
		#200 reset = 0;
		// ... сценарий ...
		if (errors == 0) $display("tb_foo: 0 errors");
		else             $display("tb_foo: %0d errors", errors);
		$finish;
	end
endmodule
```

Правила, которые сэкономили время:

- **Всегда сторожевой таймер.** Если DUT не отвечает, без него симуляция висит
  до ручного kill.
- **Не ждите фронт, который мог уже пройти.** `@(negedge sig)` пропустит событие,
  если оно случилось раньше. Надёжнее — пауза/проверка уровня/состояния:
  `#(40_000);` или `wait (sig === 1'b0);` с таймаутом.
- **Самопроверка.** В конце печатайте `0 errors`; лог удобно грепать в CI.
- **Параметры времени** (`T`, `ACK_CYCLES`) — в `localparam`/`parameter`, чтобы
  можно было ускорить симуляцию.
- **Иерархические пробы** (`dut.rbyte`, `dut.state`) разрешены и очень помогают:
  можно печатать внутреннее состояние без пересборки.
- **`$time`** печатается в единицах времени модуля. При `timescale 1ns/1ps` это
  наносекунды; в логах ISim иногда видно значения в ps точности — не пугайтесь,
  ориентируйтесь на `timescale`.
- **Не пишите в один сигнал из двух `always`.** Один драйвер на сигнал.

## 7. Сборка и запуск вручную

### 7.1. Файл проекта `.prj`

```
verilog work "dut.v"
verilog work "tb_foo.v"
```

VHDL:

```
vhdl work "dut.vhd"
vhdl work "tb_foo.vhd"
```

Смешанный проект — просто перечислите оба типа.

### 7.2. Компиляция

```sh
source /opt/Xilinx/14.7/ISE_DS/settings64.sh
cd /tmp/opencode/isim_foo
/tmp/opencode/fuse_patched -intstyle ise -mt off -prj tb.prj work.tb_foo -o tb_foo
```

- `-mt off` — без многопоточной компиляции (меньше сюрпризов);
- `-prj` — список исходников;
- `work.tb_foo` — библиотека и верхний модуль;
- `-o tb_foo` — имя исполняемого файла.

Если непонятно, какой файл не собрался:

```sh
/tmp/opencode/fuse_patched -intstyle ise -mt off -v 1 -prj tb.prj work.tb_foo -o tb_foo
```

### 7.3. Запуск

`run.tcl`:

```tcl
run all
quit
```

```sh
./tb_foo -tclbatch run.tcl
```

Другие варианты:

```tcl
run 10 ms
run 1000 ns
```

### 7.4. GUI и волновые диаграммы

Batch-режим печатает только `$display`. Для диаграмм можно открыть ISim GUI
(`isim`) и проект/снимок симуляции, либо использовать `.wcfg` с набором
сигналов. Для отладки протоколов часто достаточно `$display` + иерархических
проб — это быстрее и воспроизводимее.

## 8. Что и как моделировать

### 8.1. Чистый модуль (наш случай)

Копируете только нужные `.v`/`.vhd` в ASCII-каталог, пишете TB, который
**синтезирует входные сигналы сам**. Никакой PLL, SD-карты и прошивки не нужно.

Примеры:

- `atari_sio_disk` — TB генерирует командный кадр SIO, ACK, тактирует данные,
  собирает байты и сверяет checksum;
- `atari_atr_loader` — TB изображает интерфейс `kg_l2_img` (`sdc_*`) и модель
  SRAM (`ld_req`/`ld_addr`/`ld_data`), затем проверяет заголовок и число
  записанных байт.

### 8.2. Память и FIFO

Простые модели — массивы:

```verilog
reg [7:0] mem [0:1023];
always @(posedge clk) if (we) mem[addr] <= din;
assign dout = mem[raddr];
```

Для асинхронных FIFO (как `kg_async_fifo`) просто подключите реальный модуль —
он синтезируемый и в симуляции работает как есть.

### 8.3. Примитивы Xilinx (DCM/PLL, ODDR2, BRAM)

Для `unisim`-примитивов нужны библиотеки симуляции. В ISE они обычно уже
собраны; если ISim ругается на `DCM_SP`/`ODDR2`, подключите библиотеку:

```sh
compxlib -s isim -p xc6slx25 -arch spartan6 -lib unisim -w
```

и добавьте `-L unisim` в вызов `fuse` (или `library unisim;` в VHDL).

Но **лучше не тащить PLL/DCM в модульный TB**: подайте тактовые сигналы
генераторами TB, а PLL проверяйте отдельно/на железе.

### 8.4. Видео

Цифровую часть видео можно и нужно проверять в симуляторе.

Для `atari_video`:

- TB генерирует входной поток на 28.571 МГц: `pixce`, `r_i/g_i/b_i`,
  `hblank/vblank`, `hsync_i/vsync_i`, `pal`;
- кадр: 912×624, 456 high-res пикселей в строке, 312 строк (PAL) / 262 (NTSC);
- на выходе снимаем `r_o/g_o/b_o`, `hs_o/vs_o/de_o`;
- измеряем: первый/последний активный пиксель и строку, положение окна
  640×480 внутри 720×576, длительности HS/VS/DE, число активных строк.

Так можно **без платы** подтвердить или опровергнуть вертикальное смещение и
подобрать константы (`SRC_X0`, окно source-строк и т.п.).

Что нельзя: аналоговый DAC, кабель, монитор, его допуски к sync, «no signal»,
джиттер PLL, целостность сигнала.

Для HDMI:

- параллельную часть (`hdmi_tx`: 24-бит RGB, DE, HS/VS, TMDS-энкодер,
  контрольные символы) моделировать можно;
- 5× сериализатор на 142/325 МГц — можно, но это тяжёлый прогон; обычно
  проверяют параллельную сторону и битовый порядок на коротком участке.

### 8.5. SIO/диски

Готовый пример `sim/tb_sio.v`:

- командный кадр: start + 8 бит LSB-first + stop, 5 байт
  (`device, command, aux1, aux2, checksum`);
- проверка device ID и checksum;
- ACK;
- приём 128 байт + checksum, сверка с моделью SRAM.

Для ускорения в копии DUT уменьшается `ACK_CYCLES` (3 мс → ~17 мкс) и битовый
период (52 мкс → 2 мкс). Протокол от этого не меняется.

## 9. Ограничения и типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `Failed to compile one of the generated C files` | GCC 14 + прототипы | патченый `fuse` + обёртка |
| `Analyzing Verilog file " "` | кириллица/абсолютный путь в `.prj` | относительные ASCII-пути, staging в `/tmp` |
| `unknown module <...>` | файл не указан в `.prj` | добавить строку |
| симуляция висит | ждём фронт, который уже прошёл | пауза/уровень + сторожевой таймер |
| `libICR.so => not found` | не сделан `source settings64.sh` | запускать через `bash -c 'source ...'` |
| `$time` выглядит в 1000× | точность 1 ps vs единицы ns | смотреть `timescale` |
| `WARNING:Security:42 ... subscription lapsed` | WebPACK | безвредно |
| OOM/медленно | полный top с PLL и HDMI | моделировать подмодули |

Симулятор **не проверяет**:

- fit в кристалл, LUT/BRAM/DSP, timing — это `map`, `par`, `trce`;
- аналог и монитор;
- реальную прошивку и SD-карту;
- метастабильность и джиттер.

## 10. Рецепт для другого ядра

1. Выберите модуль, который хотите проверить (протокол, загрузчик, видео).
2. Соберите список файлов: сам модуль + зависимости (память, FIFO, пакеты).
   Всё, что не является `unisim`-примитивом, лучше включить исходниками.
3. Создайте ASCII-каталог `/tmp/opencode/isim_<name>` и скопируйте туда
   исходники (или используйте `sim/run_isim.sh` как шаблон).
4. Напишите TB: тактовые генераторы, DUT, модель окружения, сценарий,
   самопроверка, сторожевой таймер.
5. Соберите `fuse_patched`, запустите `./tb -tclbatch run.tcl`.
6. Добейтесь `0 errors`, затем проверяйте синтез и железо.

Шаблон TB и скрипт запуска лежат в `sim/`. Для нового ядра достаточно
скопировать `sim/run_isim.sh`, заменить список файлов и имя верхнего модуля.

### Пример для C64/другого ядра

```sh
# 1. исходники
mkdir -p /tmp/opencode/isim_c64 && cd /tmp/opencode/isim_c64
cp /path/to/core/rtl/my_module.v .
cp /path/to/core/sim/tb_my_module.v .
cat > tb.prj <<'EOF'
verilog work "my_module.v"
verilog work "tb_my_module.v"
EOF

# 2. инструменты (если ещё нет)
/path/to/sim/fix_isim_gcc.sh

# 3. сборка и запуск
bash -c 'source /opt/Xilinx/14.7/ISE_DS/settings64.sh >/dev/null; \
  cd /tmp/opencode/isim_c64; \
  /tmp/opencode/fuse_patched -intstyle ise -mt off -prj tb.prj work.tb_my_module -o tb_my_module'
./tb_my_module -tclbatch run.tcl
```

## 11. Наши готовые тестбенчи

### `sim/tb_sio.v` — 1050 SIO responder

Проверяет:

- приём командного кадра `31 52 01 00 84` (device 1, `R`, sector 1);
- checksum и device ID;
- ACK;
- выдачу 128 байт сектора 1 из модели SRAM и checksum;
- отсутствие лишних байт.

Ожидаемо: `tb_sio: 0 errors`.

Найденный этим тестом баг: после байта с последним битом `0` приёмник
принимал тот же низкий уровень за новый старт-бит. Исправлено флагом
`rx_armed` (взвод по высокому стоп-биту).

### `sim/tb_atr_loader.v` — загрузчик ATR

Проверяет:

- копирование образа 90K (181 сектор по 512 байт) в модель SRAM;
- разбор заголовка: `ssize=128`, `scount=720`;
- `loading` снимается, `atr_ready=1`;
- содержимое первых байт и общее число записей (92 672).

Ожидаемо: `tb_loader: 0 errors, 92672 bytes written`.

### Планируемый `sim/tb_video.v`

Генерация PAL-кадра 912×624 → `atari_video` → отчёт о положении активной
области в 720×576. Это следующий шаг для проверки вертикальной центровки без
платы.

## 12. Идея для CI

В контейнере со старым GCC (или с патченым `fuse`) можно гонять:

```sh
sim/run_isim.sh sio  | tee sio.log
sim/run_isim.sh atr  | tee atr.log
grep -q '0 errors' sio.log atr.log
```

Это ловит регрессии в протоколах до синтеза. Полный `map/par` в CI тяжелее —
его можно запускать отдельной ночной сборкой.
