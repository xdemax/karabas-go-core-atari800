# ATR и прямой XEX

## 1. ATR

`atari_atr_loader` (clk_host + clk) получает от firmware образ как поток
512-байтных секторов и складывает файл в SRAM по `0x300000`. Заголовок ATR
(16 байт) читается в `hdr`, из него берутся `ssize` (128/256) и число
секторов. `atari_sio_disk` отвечает на SIO-команды 1050 из этой же SRAM:

- сектора 1..3 — по 128 байт (boot record);
- дальше — по `ssize` (128/256).

Историческая ошибка: `sdc_rd` удерживался до `sdc_done`, mounter видел его
ещё раз в `S_IDLE` и запускал **spurious second read**; файл сдвигался на
512 байт (361 чтение на 360, ноль на LBA181/144). Сейчас:

- старт в `S_IDLE` только при `!sdc_busy`;
- в `S_WAIT` при `sdc_busy` сбрасывается `sdc_rd[0]`;
- eject (`size32==0`) обрывает загрузку из любого состояния;
- `start_req` не перезапускает уже готовый образ (`!atr_ready`).

## 2. Прямой `.xex` в Disk-слоте

Firmware не различает `.atr` и `.xex`: в core.json Disk принимает оба.
`atari_atr_loader` определяет XEX эвристикой:

```verilog
wire atr_size_ok = (size32[6:0] == 7'd16) || (size32[7:0] == 8'd144);
wire is_xex      = (size32 != 0) && !atr_size_ok;
```

Для XEX собирается **synthetic ATR** прямо в SRAM:

```text
ATR offset 0..15    : заголовок ATR (128-байтные сектора, размер = 384 + XEX)
offset 16..527      : 512-байтный 6502-загрузчик (4 boot-сектора)
offset 528..        : сырой .xex, по 128 байт на сектор
```

`xex_prefix_rom` — этот загрузчик (Tang v2, 512 байт) + заголовок ATR.
`atr_ssize=128`, `atr_scount = 4 + ceil(size/128)`. OS читает 4 boot-сектора,
запускает загрузчик с `$0706`, а тот через SIO читает сектора 5.. и
раскладывает сегменты XEX (INITAD/RUNAD, `$FFFF`-разделители, последний
сектор с padding).

### PORTB: `$BF`, а не `$FD`

Загрузчик трижды пишет `PORTB` (`$D301`): на старте, после каждого SIO-чтения
и перед `JMP (RUNAD)`. Значение — **`$BF`**:

- bit 0 = 1 — OS ROM включён (`$C000-$FFFF`);
- bit 1 = 1 — BASIC ROM **выключен**, `$A000-$BFFF` — RAM.

Именно `$BF` использует Altirra OS coldstart (`$EF0A..$EF19`) для состояния
«BASIC off». `$FD` (bit1=0) включает BASIC ROM: игры, которые копируют код в
`$A000-$BFFF` (Miner 2049er, Montezuma, River Raid), получают «сломанный
экран» или не запускаются.

Miner 2049er для примера: сегмент `$4000-$7FFF`, стаб `$3F00-$3F30`
копирует его в `$8000-$BFFF`, `RUNAD=$3F00`. С `$BF` верхняя половина —
RAM, копия проходит; с `$FD` — уходит в BASIC ROM.

## 3. Почему FPGA-DMA до boot не работает

`xex_dma_loader` писал сегменты в Atari RAM, пока машина была в reset, затем
отпускал reset и OS грузила 3-секционный стаб. Симптом: парсер завершался
(`xex_done=1`), SIO читал 3 сектора, но на экране оставался memo pad.

Причина — Altirra OS coldstart **стирает RAM** с `$0008` до верха **до**
чтения boot-сектора:

```text
Altirra OS XL, reset $EEBF:
$EF1F  LDX $06        ; число страниц (0 = 256)
$EF21  LDY #$08
$EF23  LDA #$00
$EF25  STA $66
$EF27  STA $67
$EF29  STA ($66),Y    ; очистка с $0008
...
$EF31  BNE $EF29
```

Поэтому все DMA-сегменты исчезали; стаб прыгал в `$4000` (нули) → `BRK`/
warmstart → memo pad. Прямой `JMP` вместо `JMP ($02E0)` был нужен, но его
одного мало: векторы чистятся вместе со всей RAM.

`xex_dma_loader.v`/`xex_boot_stub.v` оставлены в дереве, но **не
инстанцируются**. Если понадобится быстрый старт — делать DMA **после**
coldstart:

1. до boot в SRAM только 3-секционный стаб (не сегменты);
2. стаб пишет magic в `$3F00` и опрашивает `$3F01`;
3. FPGA по magic парсит XEX (RAM уже очищена) и последним пишет `$3F01=1`;
4. стаб читает `$02E0/$02E2`, вызывает INITAD и прыгает в RUNAD;
5. писать в RAM лучше через штатный DMA-порт ядра
   (`DMA_FETCH`/`DMA_ADDR`/`DMA_WRITE_DATA`/`MEMORY_READY_DMA`), а не через
   `ld_*`: в `atari_sram` нет очереди для `ld_req`, одиночный импульс может
   потеряться, если контроллер занят CPU/ANTIC.

Подробнее: `doc/XEX_DMA_COLDSTART_CLEAR.md`.

## 4. Ограничения

- Скорость: 128 байт/сектор через SIO; большая игра грузится десятки секунд.
- BASIC всегда выключен загрузчиком; для программ, которым нужен BASIC,
  XEX-путь не подходит (ATR с DOS/BASIC — да).
- Загрузчик пишет базовые 64K; расширенные банки переключает сама игра.
- Файлы, у которых размер случайно выглядит как ATR
  (`16 + 128n` или `400 + 256n`), будут приняты за ATR — редкость.
- `$0700-$08FF` занят загрузчиком: сегмент, который грузится туда, его
  перезапишет (как и у классического 6502-загрузчика).
