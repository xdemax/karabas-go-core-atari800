# Использование `atari_video.v` для других ретро-компьютеров

## Коротко

Модуль можно использовать как **выходной каскад 15 кГц RGBS → 720×576/720×480**
для другого ядра, но он не является универсальным скалером.

Сейчас он жёстко рассчитан на геометрию Atari:

- 456 source-пикселей в строке;
- 1824 такта `clk` на source-строку;
- 312 строк PAL / 262 строки NTSC;
- source hsync в начале строки;
- активная область source `x = 68..443`;
- два выходных пикселя на один source-пиксель.

Если у другого компьютера другая ширина строки, число строк или частота
строк, нужен front-end (line buffer/resampler) или правка параметров модуля.
Для источника с такой же 15 кГц/50 Гц геометрией модуль подключается почти
как есть.

## Интерфейс

| Порт | Направление | Разрядность | Назначение |
|---|---|---:|---|
| `clk` | in | 1 | 28.571 МГц; тактовая частота выходного растра |
| `rst` | in | 1 | активный высокий сброс |
| `pixce` | in | 1 | один такт на один source-пиксель; в Atari-варианте — каждый 4-й такт `clk` |
| `r_i`, `g_i`, `b_i` | in | 8+8+8 | цифровой RGB источника |
| `hblank` | in | 1 | активный высокий гашение строки |
| `vblank` | in | 1 | активный высокий гашение кадра |
| `hsync_i` | in | 1 | активный высокий строчный синхроимпульс |
| `vsync_i` | in | 1 | активный высокий кадровый синхроимпульс |
| `pal` | in | 1 | 1 = PAL (312 source-строк), 0 = NTSC (262) |
| `r_o`, `g_o`, `b_o` | out | 8+8+8 | RGB на выходной растр |
| `hs_o` | out | 1 | выходной hsync |
| `vs_o` | out | 1 | выходной vsync |
| `de_o` | out | 1 | output data enable, 720 пикселей |

Важно: это **не аналоговый RGBS-вход**. На вход подаются уже цифровые
уровни 3.3 В (или через level shifter) и отдельные `hsync_i` / `vsync_i`.
Композитный sync нужно сначала разложить на H/V синхру.

## Тайминг источника (текущая версия)

```text
source line: 1824 clk
source pixel: pixce = 1 каждый 4-й clk  (456 пикселей)
hsync_i: high в начале source-строки, один импульс на строку
vsync_i: high не меньше VS_MIN (256 clk), в Atari — 3 строки
visible source x: 68..443
active source: 312 строк PAL / 262 NTSC
```

`hsync_i` и `vsync_i` детектируются по **переднему фронту**. `vsync_i`
должен быть достаточно длинным; короткий импульс отбрасывается.

## Тайминг выхода

PAL (`pal=1`):

```text
line:     912 clk
DE:       720 clk (0..719)
HS:       64 clk (732..795; в top может быть 744..807)
VS:       5 строк (581..585)
frame:    624 строки
picture:  source 44..283 → output DE 48..527
```

NTSC (`pal=0`):

```text
line:     912 clk
DE:       720 clk
VS:       490..494
frame:    524 строки
picture:  480 строк
```

`de_o` не сжимается: за пределами picture (PAL `vc < 48` или `vc >= 528`)
RGB принудительно чёрный, но DE остаётся 576 строк. Это сделано, чтобы
монитор/скейлер видел стабильные 720×576.

## Путь сигнала

```text
     RGBS source
          |
          v
  sync separator  ---> hsync_i, vsync_i
          |
          v
  +-------------------+
  |  source pixel    |
  |  front-end       |  pixce, r_i/g_i/b_i, hblank/vblank
  +-------------------+
          |
          v
  +-------------------+
  |   atari_video     |
  |                   |
  |  line_a/line_b    |  two 456-pixel line buffers
  |  free-run raster  |  912×624 / 912×524
  |  h/v phase lock   |
  +-------------------+
          |
          v
   r_o/g_o/b_o, hs_o, vs_o, de_o
          |
          v
   VGA DAC / HDMI / OSD
```

## Что делает модуль

1. Пишет source-пиксели в две line-буферные линии (`line_a`, `line_b`) по
   `pixce`.
2. По hsync выбирает последнюю завершённую строку и выводит её **два раза**
   (line doubling), с горизонтальным растяжением ×2.
3. Ведёт **свободно бегущий** выходной растр 912×624 (PAL), поэтому пропавший
   source hsync/vsync не растягивает и не рвёт выходную синхру.
4. Малые ошибки фазы подтягивает по 1 такту за строку; большие — только после
   трёх подтверждений. Это защита от глитчей source-синхры.
5. Вне picture-окна выводит чёрный RGB, не меняя DE.

Это **line doubler + re-sync**, а не frame buffer. Если source сам меняет
страницу/режим в середине кадра, модуль покажет это так же, как оригинальное
железо; he не «лечит» page flipping.

## Как подключить другой компьютер

### Вариант A: источник близок к Atari

Если есть 15 кГц, 50 Гц, около 456 пикселей в строке и 312 строк:

- подать `hsync_i`, `vsync_i` (active high);
- подать `pixce` с частотой source-пикселей (в Atari — `clk/4`);
- подать RGB и `hblank`/`vblank`;
- выставить `SRC_X0`, `SRC_W`, `PIC_LEFT`, `PAL_VK` под активную область;
- `pal=1` для 50 Гц, `pal=0` для 60 Гц.

### Вариант B: другая ширина/число строк

Модуль нужно адаптировать:

- `SRC_PIX` (сейчас 456) — размер line buffer;
- `H_TOTAL` (сейчас 912) — длина выходной строки;
- `H_LAG`, `H_WIN`, `HS_MIN`, `HS_WD` — под период source hsync;
- `PAL_VK` / `NTSC_VK` — под положение vsync;
- `SRC_X0` / `SRC_W` / `PIC_LEFT` — под активное окно.

Если source-строка не укладывается в 1824 такта или пикселей больше 456,
проще поставить перед модулем **line buffer/resampler**, который приводит
источник к 456×312/262 и выдаёт `pixce`. Иначе line buffer переполнится или
картинка будет обрезана.

### Вариант C: композитный sync

Нужен sync separator (LM1881, FPGA-сепаратор и т.п.):

- `hsync_i` — отдельная строчная синхра, active high;
- `vsync_i` — кадровая, active high, длиной не меньше `VS_MIN`;
- если у источника sync отрицательный, поставить инвертор.

### Вариант D: interlace

Модуль **не поддерживает interlace**. `interlace_enable` в Atari-ядре
принудительно 0; поля идут как независимые 240-строчные кадры. Для
настоящего interlace нужен отдельный weave/frame buffer — это не текущий
`atari_video`.

## Ограничения

- фиксированный выход 720×576/720×480, не произвольный скалер;
- нет композитного sync на входе;
- нет interlace;
- нет frame buffer и деинтерлейсинга;
- нет OSD/аудио — это отдельные блоки;
- source должен иметь стабильную строку/кадр; иначе модуль будет
  ресинхронизироваться, но картинка может прыгать;
- page flip/tearing source не исправляется;
- для аналогового RGBS нужен level shifter/ADC, модуль только цифровой.

## Пример инстанса

```verilog
atari_video #(
    .SRC_X0   (10'd78),
    .SRC_W    (10'd356),
    .PIC_LEFT (10'd4),
    .HS_START (10'd732),
    .HS_END   (10'd796),
    .PAL_VK   (10'd584),
    .NTSC_VK  (10'd494)
) video (
    .clk      (clk_vid),
    .rst      (reset),
    .pixce    (source_pixce),
    .r_i      (source_r),
    .g_i      (source_g),
    .b_i      (source_b),
    .hblank   (source_hblank),
    .vblank   (source_vblank),
    .hsync_i  (source_hsync),
    .vsync_i  (source_vsync),
    .pal      (is_pal),
    .r_o      (vga_r),
    .g_o      (vga_g),
    .b_o      (vga_b),
    .hs_o     (vga_hs),
    .vs_o     (vga_vs),
    .de_o     (vga_de)
);
```

## Проверка

Для Atari-геометрии есть три теста:

- `tb_video_standard_timing` — 912-тактная строка, DE 720, HS 64, 624 строки,
  pair check;
- `tb_video_glitch` — пропажа/лишняя HS/VS, короткая/длинная строка;
- `tb_video_frame` — геометрия картинки и PPM-кадр.

Текущие результаты: `0 failure(s)` во всех трёх, `pair check 0 mismatched`,
`first=91`, `DE lines 576`, `frame 569088`.
