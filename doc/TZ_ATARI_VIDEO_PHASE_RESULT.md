## 0. Новое с железа (2026-11-21): Numen на деревьях

После прошивки 4.1 с фазовым фиксом:

- меню/BASIC и обычный текст выглядят **отлично**, шов/двоение ушли;
- Numen доходит до сцены с зелёными деревьями;
- **на деревьях картинка двоится и прыгает**;
- похоже на специальные графические режимы Numen (GTIA/ANTIC, interlace/переключения режимов), которые текущий `atari_video` не обрабатывает.

Это уже не шов line-pair: pair check проходит. Нужно отдельно разобрать special modes/interlace.

### Что проверить в первую очередь

1. В `atari800_machine.v` сейчас жёстко:
   ```verilog
   .interlace_enable(1'b0)
   ```
   а `VIDEO_ODD_LINE`/`VIDEO_START_OF_FIELD`/`interlace` не заведены в `atari_video`. Если Numen использует interlace, текущий тракт показывает поля как независимые кадры → двоение/прыжки.
2. `atari_video` должен принимать `interlace`, `odd_line`, `start_of_field` (или эквивалент) и:
   - при `interlace=0` работать как сейчас;
   - при `interlace=1` не двоить и не прыгать: либо weave двух полей, либо стабильно показывать одно поле без изменения геометрии;
   - не сбрасывать/не сдвигать кадр на каждом field-vsync.
3. Проверить mid-frame переключения GTIA/ANTIC (9/10/11, hi-res, VSCROL): line buffer не должен показывать старую/соседнюю строку, pair check должен остаться 0.
4. Проверить, не меняется ли у Numen число активных строк/положение VS на деревьях; при смене режима кадр не должен «прыгать» по вертикали.
5. Если есть возможность — снять VCD/логику `hsync_i`, `vsync_i`, `hblank`, `vblank`, `pixce`, `VIDEO_ODD_LINE`, `interlace` на сцене деревьев. По ним точно видно, interlace это или переключение режимов.

### Что менять

- GTIA/ANTIC/POKEY/CPU/память/прошивку **не трогать**.
- Изменения в `atari800_machine.v`/`karabas_*_top.v` для `interlace_enable`/`odd_line` — отдельным патчем с описанием.
- Фазовый фикс и `pic_blank` сохранить; pair check и `EXPECT_FIRST=91` не ломать.
- 4.2 (27.027) пока отложить: на обычном тексте картинка уже резкая; если на деревьях останется мыло, вернуться к 4.2 отдельно.

### Новые тесты

- `tb_video_interlace`: два поля, `odd_line` 0/1; проверить отсутствие двоения/прыжков, стабильные HS/VS/DE, 576 активных строк.
- `tb_video_modes`: GTIA 9/10/11, hi-res, mid-frame переключение, VSCROL; pair check 0.
- `tb_video_numen` (по возможности): синтетическая последовательность «нормальная сцена → деревья/спецрежим → обратно»; кадр не двоится и не прыгает.

## Про FAIL `DE-rise->HS-rise 732..44508`

Это баг **теста**, не RTL:

- `t_de_rise` не сбрасывается, пока DE low в вертикальном гашении;
- HS в это время продолжают идти, и тест меряет их от последнего DE-rise;
- `44508 = 48*912 + 732`.

Правильно: мерить HS только если `now - t_de_rise < 912` (или очищать `t_de_rise` по `vs_o`). Тогда off = 732.
