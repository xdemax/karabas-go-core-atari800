# ТЗ: новый `atari_video.v` для Atari 800XL (Karabas Go / Mini / MiniG)

## 1. Задача

Заменить текущий `src/rtl/atari_video.v` на корректный видеотракт, который стабильно показывает все режимы Atari 800XL, включая быстрые переключения GTIA/ANTIC, interlace и сцены Numen, и не даёт чёрный экран/обрывки кадра/потерю синхры.

Проблема на железе (PAL, 320K Rambo, Numen Side A + Side B):

- первый кадр интро показывается;
- затем экран чернеет;
- через пару секунд видны обрывки «зелёных деревьев»;
- затем опять чернота и зависание;
- не исключена потеря синхры монитором.

`gtia.vhdl`, `gtia_player.vhdl`, `gtia_priority.vhdl`, `gtia_priority_store.vhdl`, `gtia_palette.vhdl`, `antic.vhdl` **идентичны upstream MiSTer** (проверено diff). Поэтому менять их нельзя и не нужно. Ответственность за исправление — на `atari_video.v` и его интеграции.

## 2. Что нельзя менять

- Не менять `src/a8core/*` (GTIA, ANTIC, POKEY, CPU, address decoder, core top).
- Не менять прошивку/OS ROM, ATR loader, SIO, память, тактовые генераторы.
- Не менять `karabas_*_top.v` и `atari800_machine.v` без отдельного согласования. Если для interlace нужен новый порт — предложить патч интеграции отдельно, не делать его «заодно».
- Не менять формат выходного кадра без необходимости: PAL 720×576@50 — основной целевой режим. NTSC не должен деградировать.
- Не использовать второй тактовый домен. Весь модуль работает на `clk` (28.571 МГц, `cycle_length=16`).

## 3. Текущий интерфейс

`src/rtl/atari_video.v` сейчас имеет:

```verilog
module atari_video #(
    parameter [9:0] SRC_X0   = 10'd78,
    parameter [9:0] SRC_W    = 10'd356,
    parameter [9:0] PIC_LEFT = 10'd4,
    parameter [9:0] HS_START = 10'd816,
    parameter [9:0] HS_END   = 10'd888
) (
    input  wire       clk,
    input  wire       rst,
    input  wire       pixce,
    input  wire [7:0] r_i, g_i, b_i,
    input  wire       hblank,
    input  wire       vblank,
    input  wire       hsync_i,
    input  wire       vsync_i,
    input  wire       pal,
    output reg  [7:0] r_o, g_o, b_o,
    output reg        hs_o,
    output reg        vs_o,
    output reg        de_o
);
```

Интеграция:

- `atari800_machine.v` подаёт `VIDEO_PIXCE`, `VIDEO_R/G/B`, `HBLANK`, `VBLANK`, `VIDEO_HS`, `VIDEO_VS`, `PAL`.
- `VIDEO_PIXCE` — это `ANTIC_HIGHRES_COLOUR_CLOCK_OUT` (2× цветовой клок, 456 импульсов на строку).
- `hblank`/`vblank` — из GTIA; активны высоким уровнем (проверить по факту, но текущая логика считает их active-high).
- `hsync_i`/`vsync_i` — из GTIA; текущая логика считает их active-high (`hs_rise = hsync_i & ~hs_d`).
- `hs_o`/`vs_o` — active-high; на VGA в `karabas_go_top.v` инвертируются (`VGA_HS = ~osd_hs`), на HDMI идут в `kg_hdmi_ft`/`atari_hdmi` как есть.
- Параметры `HS_START/HS_END`: Go — 816/888 (VGA, есть front porch), Mini/MiniG — 840/912 (HDMI).
- `interlace`/`VIDEO_ODD_LINE`/`VIDEO_START_OF_FIELD` сейчас **не заведены** в `atari_video`; `interlace_enable` в `atari800_machine` жёстко `0`. Это отдельное отличие от MiSTer; если для решения нужен interlace, предложить изменение интеграции отдельным пунктом.

## 4. Что обязан поддерживать новый модуль

### 4.1. Источник

- 456 high-res пикселей на строку, `pixce` 7.14 МГц (один импульс на 4 такта `clk`).
- PAL: 312 строк в поле/кадре, 240 видимых строк.
- NTSC: 262 строки, 240 видимых.
- Строка может быть короче/длиннее по числу активных пикселей; модуль не должен зависеть от жёсткого «ровно 456» для синхронизации.
- Пиксельный поток уже содержит результат GTIA: normal/high-res, GTIA 9/10/11, players/missiles, mid-line изменения. Модуль **не декодирует** режимы ANTIC/GTIA; он обязан не терять пиксели и не зависеть от режима.
- В GTIA-режимах цвет меняется на цветовом клоке (2 high-res пикселя на цвет); в high-res — на каждом high-res пикселе. Оба случая — просто поток `pixce` + RGB.

### 4.2. Синхронизация и кадр

- Выходная синхра должна генерироваться **локально** и не пропадать при:
  - пропаже/дребезге `hsync_i`/`vsync_i`;
  - короткой/длинной строке;
  - лишнем/пропущенном HS/VS;
  - переключении режима/частоты;
  - interlace-полях.
- При потере источника модуль обязан:
  - продолжать выдавать HS/VS/DE в штатном формате;
  - показывать последний корректный кадр или чёрный кадр (без «мусора» и без потери синхры);
  - автоматически восстановиться, когда источник вернётся.
- Нельзя сбрасывать выходные счётчики на каждый `vsync_i` так, чтобы короткий/дребезжащий импульс ломал кадр. Нужен фильтр/дебаунс и/или free-running счётчик с мягкой подстройкой.
- Нельзя останавливать `oline`/`de_o` из-за `frame_pend`, если HS пропал. Текущая логика `frame_pend` — главный подозреваемый в «обрывках/чёрном».

### 4.3. Line buffer

- Минимум два полных line buffer по 456×24 бит (BRAM), ping-pong.
- Запись — на `pixce`; чтение — на `clk`; чтение и запись не должны конфликтовать.
- Запись строки не должна обрезаться, если `pixce` пришёл раньше/позже `hsync`.
- При переключении режима/строки нельзя читать буфер, который ещё пишется.
- Если строка короче 456 — недостающие пиксели заполнять чёрным/последним, но не оставлять старый мусор.
- Если строка длиннее — лишние пиксели игнорировать после 456, не затирая начало буфера.
- При interlace: как минимум не ломать кадр; в идеале — использовать `odd_line`/`field` для выбора поля/смещения. Деинтерлейс 2 полей в 480 строк — опционально, но не в ущерб стабильности 50 Гц.

### 4.4. Выходной формат

Основной (PAL):

- 720×576 active, 912×624 total (как сейчас), 50 Гц.
- HS: 72 пикселя, позиция `HS_START..HS_END` (Go 816..888, Mini/MiniG 840..912).
- VS: 5 строк, позиция как сейчас (PAL `vs_start=581`).
- `H_START=96`, `H_ACTIVE=720`; картинка 712×480 внутри 720×576, боковые поля 4 пикселя (как сейчас), если не согласовано иное.
- Источник: 356 пикселей `SRC_X0=78..433`, удвоение по X, 240 строк → 480 строк.
- Цвет — 8 бит на канал, без изменения палитры.

NTSC:

- Сохранить совместимость с текущим поведением (720×576 output, `v_active=480`, `vs_start=490`) **или** сделать 720×480@60, но только если обновлены OSD/HDMI/VGA и тесты. По умолчанию — не ломать текущий формат.

### 4.5. Interlace (если включается)

- Модуль должен принимать (или уметь принимать) `interlace`, `odd_line`, `start_of_field` и не показывать чёрный кадр при их появлении.
- При `interlace=0` поведение — как обычный прогрессивный кадр.
- При `interlace=1`:
  - выходная синхра — стабильные 50 Гц;
  - поле не должно «прыгать»/пропадать;
  - допустим вывод каждого поля как 240 строк с удвоением (без полноценного weave), но без чёрного экрана;
  - если делается weave — нужен второй field buffer; это опционально.
- Если для interlace нужно поменять `atari800_machine.v` (`interlace_enable`, `VIDEO_ODD_LINE`), оформить это отдельным патчем/описанием, не менять топ молча.

## 5. Диагностика/наблюдаемость

Добавить (по возможности, без изменения внешнего интерфейса):

- счётчики: число source HS/VS, число output HS/VS, число пропущенных/лишних HS, число переполнений line buffer, число watchdog-срабатываний;
- при симуляции — `$display`/VCD; на железе — можно вывести в `dbg_*`/OSD, если это не ломает топ. Если вывод на железо требует изменений топа — только предложить.

## 6. Обязательные тесты

Все тесты — Verilator (и/или GHDL), без изменения ядра. Референс — текущий `sim/tb_video_frame.v` и кадры Altirra.

1. **`tb_video_frame`** — существующий тест должен проходить без регрессии (или быть обновлён только под новый интерфейс, с сохранением проверок).
2. **`tb_video_modes`**:
   - normal 320×240;
   - high-res 640 (2 пикселя/цветовой клок);
   - GTIA 9/10/11 (цвет меняется на цветовом клоке);
   - mid-frame переключение режима/цвета;
   - vertical scroll/fine scroll;
   - PAL и NTSC.
   Проверять: HS/VS периоды, DE-окно, отсутствие чёрного кадра при ненулевом входе, отсутствие обрывков.
3. **`tb_video_glitch`**:
   - пропущенный HS, лишний HS, короткая/длинная строка;
   - пропущенный/лишний VS, дребезг VS;
   - проверять, что `hs_o`/`vs_o` не пропадают, `de_o` остаётся в допустимом окне, модуль восстанавливается.
4. **`tb_video_interlace`**:
   - два поля с `odd_line` 0/1;
   - проверять отсутствие чёрного кадра/потери синхры;
   - если weave — проверить, что строки не перепутаны.
5. **`tb_video_numen`** (по возможности):
   - подать последовательность кадров, повторяющую переход «нормальный кадр → GTIA-сцена → обратно»;
   - зафиксировать, что нет чёрного кадра и обрывков;
   - сохранить PPM/PNG для визуального сравнения с Altirra.

## 7. Критерии приёмки

- На железе (PAL, Numen Side A/B) сцена «зелёные деревья» идёт непрерывно, без чёрного экрана и обрывков.
- Монитор не теряет синхру при переключениях режимов.
- OSD/HDMI/VGA работают как раньше.
- Существующие тесты проходят; новые тесты покрывают mode changes, interlace, glitch.
- Нет изменений в `src/a8core/*`, GTIA/ANTIC, памяти, SIO, прошивке.
- Синтез на Spartan-6 проходит по ресурсам/таймингу; BRAM не больше, чем доступно (минимум 2×456×24, при weave — 2 поля).

## 8. Порядок работы для исполнителя

1. Прочитать `src/rtl/atari_video.v`, `src/rtl/atari800_machine.v`, `src/rtl/karabas_*_top.v`, `sim/tb_video_frame.v`.
2. Сформулировать, какой именно сценарий ломает текущий модуль (line buffer, `frame_pend`, сброс по VS, interlace, полярность HS/VS) и подтвердить это тестом/симуляцией.
3. Предложить архитектуру (2 line buffer + free-running output timing + watchdog + опциональный interlace), до реализации.
4. Реализовать `atari_video.v`, сохранив интерфейс (или добавив новые порты с безопасными значениями по умолчанию).
5. Добавить тесты из раздела 6, прогнать, приложить логи/PPM.
6. Отдельно описать, нужны ли изменения в `atari800_machine.v` для interlace; не делать их без согласования.
7. Не коммитить/не публиковать релиз без проверки на железе.

## 9. Референс

- Altirra: 800XL, PAL, 320K Rambo, BASIC off, Side A → Side B.
- Эталонные кадры/аудио (если ещё живы): `/tmp/opencode/ref_frames/`, `/tmp/opencode/ref_intro2.wav`.
- В Altirra интро Numen использует быстрые переключения GTIA-режимов; первый кадр с полосами — переходный, затем зелёные комнаты/деревья.
- Верхнеуровневые параметры HS: Go 816/888, Mini/MiniG 840/912; PAL 720×576@50 — основной формат.
