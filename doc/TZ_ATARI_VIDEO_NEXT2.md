# Обновление для Claude: видео 4.1/4.2, что реально на железе

## 1. Факт с железа (MiniG rev G, HDMI)

Собрали и прошили 4.1 (`HS 744..808`, 28.571 МГц, 624 строки, DE 0..719):

- монитор **залочился** — сигнал появился;
- HDMI-звук **есть**;
- изображение **мыльное и как будто двоится**;
- лучше не стало по сравнению с 732/796.

То есть 4.1 решил только синхру/появление картинки. Остались именно:
- размытие (похоже на неверный пиксельный клок 28.571 вместо 27.027 / ресемплинг);
- «двоение» (проверить: дублирование строк/полей, сдвиг line-pair, ghosting по X).

## 2. Что уже сделано в коде

- `src/rtl/atari_video.v` — твоя `atari_video_std.v` + `pic_blank` (DE 576, RGB чёрный вне 48..527), H_START=0, HS 732/796 по умолчанию.
- `src/rtl/atari_video_27.v` — первая версия 4.2: 4-row ring, write `clk` 28.571, read `clk_vid` 27.027, 720x576, HS 744..808, VS 581..586, H_TOTAL 861/862 (дробная), 625 строк.
- `src/rtl/atari800_machine.v` — generate `VIDEO27` (0 = старый `atari_video`, 1 = `atari_video_27`).
- MiniG top сейчас **откатан на 4.1**: старый PLL VCO 800, `clk_sys=clk_vid=28.571`, HS 744/808, `VIDEO27=0`.
- UCF откатан на старый VCO 800.

## 3. Что получилось с 4.2

Симуляция `tb_video_27` (28.571/27.027):

```text
DE 720..723, HS 64, line 861..862,
DE lines 576, frame ~537639
```

Функционально базовая развёртка идёт, но сборка **не проходит тайминг**:

```text
TS_pll_clk_0_: requirement 35 ns, actual 114.107 ns, errors 4059
Timing Score: 12137547
```

То есть PLL VCO 1000 / auto-constraints дают неверный `clk_sys` (фактически ~8.7 МГц в анализе), и валятся пути `atari_sram`/`atari_sio_disk`. Прошивать это нельзя.

## 4. Что нужно доделать

1. **Не менять старый PLL 800 МГц** для `clk_sys=28.571`.
2. 27.027 МГц получить **отдельно**:
   - вторым PLL/DCM, либо DCM_CLKGEN от 50 МГц;
   - не через VCO 1000 на общем PLL, пока не разобрана причина `actual 114 ns`.
3. Добавить/проверить constraints:
   - `TS_SYS` (35 ns) на `clk_sys`;
   - `TS_VID` (37 ns) на `clk_vid`;
   - from-to `TG_SYS <-> TG_VID` (31 ns), `TG_VID <-> TG_HOST`, HDMI `pclk`.
4. Собрать 4.2 и добиться **Timing Score 0** до bitstream.
5. Проверить на мониторе: не должно быть мыла и двоения.
6. Отдельно проверить «двоение»:
   - нет ли повтора одной source-строки в двух выходных (line-pair);
   - нет ли ghosting по X из-за 28.571/27.027;
   - нет ли дублирования полей/строк из-за 624/625 и sync-event.

## 5. Требования к 4.2

- 720x576@50, DE `0..719`, 576 активных строк;
- HS `744..808` (24 px front porch) или `732..796` (12 px); VS `581..586`;
- 625 строк, H_TOTAL дробный (861/862) для совпадения с source-кадром 569088 тактов;
- 4-row ring: запись `clk`, чтение `clk_vid`, без чтения/записи одного ряда;
- source 456 px -> output 720, окно `SRC_X0=78`, 2x, картинка 48..527;
- RGB-выход чёрный вне 48..527, **DE не сжимать**;
- при пропаже source HS/VS — синхра/DE продолжаются, картинка чёрная, затем восстановление;
- интерфейс/топы менять только с отдельным патчем и описанием.
